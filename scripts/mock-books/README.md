# Gotigin mock books (internal demos / learning)

Plain SQLite **app backups** for the four Kumkaj products. Not a separate
playground product — restore them into a real install the same way as any
owner backup.

Generated by Store APIs (`apps/*/tests/mock_books.rs`) + `VACUUM INTO`
(`Store::backup_to`). Owner PIN on every file: **1234**.

## Files

| App | Path | Shop face |
|---|---|---|
| Khaynjo | `khaynjo/khaynjo.sqlite3` | Gotigin Demo Kitchen |
| Moklanjo | `moklanjo/moklanjo.sqlite3` | Gotigin Swift Courier |
| Kirano | `kirano/kirano.sqlite3` | Gotigin Neighbourhood Kirana |

Each file holds **21 days** of trading (sales/bookings via `SaleDraft.user_at`),
catalogue, parties, staff, and expenses/purchases where the schema supports them.

## Restore

### In-app (preferred)

1. Quit the app.
2. Copy the file to the app data backups folder as `restore.sqlite3`:
   - Linux: `~/.local/share/<app-id>/backups/restore.sqlite3`
   - Or with a custom data dir: `$KUMKAJ_DATA_DIR/backups/restore.sqlite3`
3. Launch → More → **Backup & settings** → **Restore backup**.
4. Unlock with Owner PIN **1234**.

App ids (packaged): `com.khaynjo`, `com.moklanjo`, `com.kirano`, `com.tabiyat`
(dev builds may use `*.debug` — see each app’s `env/development.env`).

### Dev copy

You can also point a fresh data dir at a seeded Server folder under
`.work/<app>/` after generation, or open the `.sqlite3` with
`Store::open_path` in tests. For UI look-at sessions prefer Restore so
`meta.app` / schema checks run the same path as owners.

Canonical notes: `docs/DEV.md` § Backup format / Restore.

## Regenerate

From the workspace root (needs `sqlite3` on PATH for expense-day stamping
and verify):

```bash
./scripts/mock-books/generate.sh           # all four
./scripts/mock-books/generate.sh khaynjo   # one app
MOCK_BOOKS_OUT=/path/to/out ./scripts/mock-books/generate.sh
./scripts/mock-books/verify.sh
```

`local/` is gitignored — keep generated DBs local for demos.

## Gaps / notes

- `tests/visual_seed.rs` stays thin (screenshot states). Multi-day demos use
  `tests/mock_books.rs` + `scripts/mock-books/generate.sh`.
- Expense and purchase rows cannot take `user_at` on the public Store API yet;
  generators encode `DAY:YYYY-MM-DD|…` in the note and rewrite timestamps with
  `sqlite3` after the Store handle closes. Sales/bookings use `SaleDraft.user_at`.
- Moklanjo line amounts are **slab freight**, not `unit_price × weight`; verify
  checks `sum(lines) = lines_total` instead of unit×qty for that app.
- Open KOTs (Khaynjo) and a few booked AWBs (Moklanjo) are left live so Floor /
  Ops are not empty after restore.
- No site deploy; `local/` is gitignored.
